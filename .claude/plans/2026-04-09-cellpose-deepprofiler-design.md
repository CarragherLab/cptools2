## Problem Statement

The cptools2 Nextflow pipeline has illumination correction wired up (ILLUM_CALCULATE + ILLUM_APPLY) and feature extraction scaffolded (FEATURE_EXTRACT), but the segmentation stage is a dead-end CellProfiler template that does not match the actual downstream requirements. The three load-bearing problems:

1. **Segmentation**: The current `nuclear_segmentation.cppipe` template assumes input filenames like `..._CorrDNA.png`. The illum_apply template outputs `..._w1_CorrDNA.png` (filename mismatch). The template exports a single combined CSV, not per-site CSVs (format mismatch with DeepProfiler).
2. **Feature extraction bridge**: DeepProfiler requires an `index.csv` that lists every (plate, well, site) row with per-channel image paths. DeepProfiler's `setup` command only creates directories — it does not auto-generate this file. No generator exists anywhere in cptools2.
3. **Model weights**: The DeepProfiler container has no pretrained checkpoint baked in. The Cell Painting CNN weights (`combinedset_cellsout_e30.hdf5`, ~20MB from Zenodo record 7114558) are not deployed anywhere on Eddie.

The user wants Cellpose-SAM for segmentation (not CellProfiler), w1/w2/w3 naming preserved throughout, no plate map dependency, weights stored alongside containers on Eddie, and a clean end-to-end walkthrough.

## Constraints

- **Eddie HPC SGE environment**: GPU jobs use `gpu-a100` parallel environment with `-l gpus=N`, non-login shells require `. /etc/profile.d/modules.sh`, `--nv` flag for Singularity GPU passthrough, `h_rss` not `h_vmem` for memory
- **Deployed containers**: `cellprofiler_4.2.8.sif`, `cellpose_sam_1.0.sif`, `deepprofiler_1.0.sif` already live on both chandranlabs and Drug-Discovery group spaces (from Loop 210). Rebuilds are expensive (~4 hours of debugging based on Loop 210 retro).
- **Filename convention**: User will use `{Plate}_{Well}_s{Site}_w{N}.tif` (ImageXpress canonical). Channel number is the ground truth, semantic names (DNA/RNA/etc.) are internal to the cppipe only.
- **Nine cell lines**: Morphological variation across the assay means segmentation tuning is painful. SAM's generalization is the main argument for Cellpose over CellProfiler IdentifyPrimaryObjects.
- **No plate map required at pipeline run time**: Treatment metadata is optional; pipeline stubs Treatment="untreated", Replicate=1 if no plate map provided.
- **Test suite baseline**: 148 tests currently pass. New work must not regress that.
- **Branch strategy**: Clean rewrite on `ai-update`, no backward-compat dual paths (per user preference in memory).

## Premises (all confirmed)

1. **Cellpose-SAM is the right segmentation tool.** SAM generalizes across the user's 9 cell lines without per-lineage parameter tuning. GPU container already deployed.
2. **DeepProfiler needs a pipeline-generated `index.csv`.** Verified via DeepProfiler handbook — `setup` only creates directories. Must be generated.
3. **Pretrained weights live alongside containers on Eddie, not baked in.** 20MB file, separation of concerns, updateable without Docker→Singularity→Eddie rebuild pain. Deploy to `/exports/cmvm/eddie/scs/groups/chandranlabs/cptools2/models/combinedset_cellsout_e30.hdf5` and mirror to Drug-Discovery.
4. **w1/w2/w3 naming throughout the pipeline.** Generic, adapts to any channel count, downstream parquet assembly applies a config-driven w-number → semantic-name mapping for pycytominer compatibility.
5. **Can run DeepProfiler without a plate map.** Generator stubs Treatment="untreated" and Replicate=1 by default; optional `--plate-map` flag joins real metadata if the user has it.
6. **Scope excludes cell masks, pycytominer integration, DinoV2, and any multi-model dispatch.** Nuclei only, one model, one feature extractor.
7. **Illumination templates must be rewritten for w-number naming.** Non-optional — without it, cellpose filename filter breaks.
8. **Two ralph loops, not one.** Loop 230 = all new code + tests + docs (green locally). Loop 240 = end-to-end Eddie validation (the work that was originally Loop 230). Risk split by keeping GPU-queue-dependent work behind a gate.

## Approaches Considered

### Approach A: Minimal Viable Lane
Just the cellpose module + index.csv generator. Defer illum template updates. Make the cellpose script tolerate `..._w1_CorrDNA.png`-style filenames via a flexible regex.

- Effort: S | Risk: Med | Completeness: 5/10
- Downside: template state remains inconsistent; deferred work becomes Loop 240 work anyway; filename logic spread across template + script

### Approach B: Complete Lane (CHOSEN)
Full refactor in one coherent scope. Templates → w-number + TIFF. Cellpose-SAM Python script via Nextflow `bin/`. `make_deepprofiler_index.py` bridge. Weights deployment script. DeepProfiler config updated. New user-facing docs. Tests for every helper. Split across Loop 230 (code) + Loop 240 (Eddie end-to-end).

- Effort: M | Risk: Low | Completeness: 9/10
- Reuses: parserix filename parsing, scissorhands SGE patterns, existing illum + feature_extract Nextflow scaffolding, guide_03 design decisions

### Approach C: Lateral — DinoV2 pivot
Skip DeepProfiler + segmentation entirely. Full-image embeddings via a foundation ViT.

- Effort: M | Risk: High | Completeness: 3/10
- Rejected: changes the analytical output entirely, abandons deployed infrastructure, different project

## Open Questions (RESOLVED in plan-eng-review 2026-04-09)

1. **Weights bind-mount strategy**: Use Singularity `--bind $WEIGHTS_DIR:$WEIGHTS_DIR:ro` in the Nextflow process + `ln -s $params.feature_extraction.weights_path dp_project/outputs/cell_painting/checkpoint/` inside the script. Config.json `checkpoint` field stores the filename only. The `cell_painting` experiment name comes from existing feature_extract.nf pattern (line 41). Add `resolve_weights_path()` to `cptools2/containers.py` mirroring `resolve_container_dir()`, with `CPTOOLS2_WEIGHTS_DIR` env var support.
2. **Script location + importability**: BOTH. Thin CLI wrappers at `nextflow/bin/run_cellpose_segmentation.py` + `nextflow/bin/make_deepprofiler_index.py`. Importable libraries at `cptools2/cellpose_segmentation.py` + `cptools2/deepprofiler_index.py`. Tests import from the cptools2 package. Entry scripts are small enough that they don't need their own tests; integration test in Loop 240 covers end-to-end.
3. **Cellpose batch size**: Default **8** (conservative, safe on A100 80GB for 1080×1080 16-bit images). Expose as `segmentation.batch_size` YAML key. Tune upward in Loop 240 based on actual throughput.
4. **Illum cppipe regression risk**: LOW. No existing tests exercise cppipe templates directly (they're CellProfiler pipelines, not Python). Integration validation happens in Loop 240 (end-to-end Eddie test). A broken cppipe fails loudly at SGE job start, not silently.
5. **Filename parsing DRY**: BOTH new scripts reuse `parserix.parse.img_channel/well/site/plate_name` — verified via test that parserix handles both `.tif` and `.tiff` extensions and returns channel as integer. No custom regex, no new shared helper module.

Windows machine against the SMB mount — only on Eddie compute nodes after
STAGE_IN rsyncs from DataStore to scratch.

### Safety rules for these paths

1. **Never `rm`, `mv`, `touch`, or any write operation** on `U:\Datastore\...`
   or its Eddie equivalent
2. **Never `rsync --delete`** — always append-only
3. **STAGE_IN rsync is read-only on the source** — verify the flag layout before
   any real run
4. **Store intermediate outputs on scratch**, never on the datastore mount
5. **Human approval required** before any Loop 240 run that touches these paths
