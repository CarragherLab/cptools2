# Phase 2.9 Plate Export Join Repair Design

## Problem

The clean DataStore-backed Phase 2.9 full-plate run reached the CPU export
boundary after completing all GPU chunks:

```text
CELLPOSE_SEGMENT: 96/96 completed
FEATURE_EXTRACT: 96/96 completed
EXPORT_FEATURES: failed before export execution
```

`EXPORT_FEATURES` groups chunk outputs into one plate-level task. Every
`FEATURE_EXTRACT` payload currently arrives as a directory named `features`.
Nextflow cannot stage a single task input collection containing many directories
with the same staged file name, so the plate export task fails before
`cptools2 export-features` runs.

## Goal

Make the join/export path correct for full plates and future chunked feature
routes, while preserving one export-ready measurement table set per plate.

## Selected Design

### Structured Chunk Export Payloads

The `FEATURE_EXTRACT` to `EXPORT_FEATURES` handoff should carry explicit
identity:

```text
plate_id
chunk_id
feature_payload_dir
```

The native feature output and its existing stage-out behavior remain available.
The export-specific payload is allowed to become more explicit because it is the
join contract for plate-level measurement tables.

### Collision-Proof Plate Join

`EXPORT_FEATURES` should keep one CPU task per plate, but it must stage chunk
payloads into unique chunk-scoped locations before joining them. The export task
must verify the received chunk payload count and then copy or traverse the
chunk payloads into an exporter input tree without same-name directory
collisions.

The first implementation should keep DeepProfiler-specific table conversion in
the DeepProfiler exporter. The Nextflow handoff should remain generic enough for
future feature engines to carry their own payload directories.

### Canonical and Published Table Names

Canonical table names stay deterministic inside each table directory:

```text
deepprofiler_manifest.csv
deepprofiler_sites.csv
deepprofiler_cells.csv
deepprofiler_quality.csv
```

Published plate exports should also include plate identity so files remain
self-describing when copied out of the plate directory:

```text
<plate_id>__deepprofiler_manifest.csv
<plate_id>__deepprofiler_sites.csv
<plate_id>__deepprofiler_cells.csv
<plate_id>__deepprofiler_quality.csv
```

An optional caller-provided export run label may be added to published aliases:

```text
<plate_id>__<run_label>__deepprofiler_cells.csv
```

Do not generate uncontrolled wall-clock timestamps inside the exporter. Pipeline
run directories and explicit run labels provide provenance without making
canonical artifacts nondeterministic.

## Alternatives Rejected

### Rename Only Staged `features` Inputs

This is the narrowest symptom fix, but it keeps chunk identity implicit and
leaves the join contract weak. Full-plate export deserves an explicit payload
shape because the join is a public measurement boundary.

### Rename Only Upstream GPU Feature Directories

This solves the collision by changing a successful GPU process output contract.
It couples GPU extraction naming to the table join and risks churn for native
feature stage-out without giving the export step a stronger integrity check.

### Manual CLI Backfill Instead of Pipeline Repair

Backfill remains a useful recovery tool, but it does not certify the clean
pipeline path that Phase 2.9 exists to prove.

### Per-Chunk Table Export Plus Plate Merge

This is a valid future scaling path if one plate-level CPU export becomes a
measured bottleneck. It adds a table merge protocol and more partial-output
failure modes now, before evidence says it is needed.

## Integrity Checks

The repair should add tests and runtime checks for:

- multi-chunk feature payloads with repeated internal directory names;
- explicit plate and chunk identity in the export handoff;
- duplicate or missing chunk payload behavior;
- deterministic canonical table names;
- plate-aware published filenames;
- optional run label naming;
- NaN and no-cell quality behavior surviving the joined export;
- one CPU plate export task and final stage-out completion on Eddie.

## Validation

Local validation:

- focused exporter tests for naming and payload joining;
- Nextflow architecture tests for chunk-aware export handoff and plate grouping;
- any existing Phase 2.9 feature export suites touched by the naming contract.

Eddie validation:

- sync the repaired export path to the permanent Eddie mirror;
- resume or rerun the clean full-plate route at
  `/exports/eddie/scratch/mharvey2/cptools2-ai-update/diagnostics/phase-2.9-full-plate-clean-20260521/dp-growth-concurrency8`;
- record whether completed GPU work is reused when resume is available;
- require `EXPORT_FEATURES` and final `STAGE_OUT` to complete;
- collect full plate `.npz`, mask, table, row-count, runtime, and stage-out
  evidence before Phase 2.9 is passed.
